# I18n Data Locale Strategy

## Current Baseline

- English remains the default unprefixed locale and source of truth.
- `zh-Hans` has full data overlay coverage for the current structured data sets:
  - fish, shops, crops, gardening, insects, recipes, codes, events, npcs, pets, hobbies, tools.
- Locale data overlays live under `src/data/content/i18n/<locale>/data/`.
- `npm run validate:data` validates overlay schema, source ID matching, empty overlay rows, and zh-Hans quality checks.
- `npm run report:i18n:data` reports data overlay coverage by locale and is included in `npm run qa`.

## Next Locale Order

1. `zh-Hant`
   - Lowest-risk next data locale because several imported Wiki source names and lore fields already originate from Traditional Chinese.
   - Best for proving that the overlay system supports sibling Chinese locales without reusing the Simplified Chinese quality rules blindly.
   - Should not be generated by converting `zh-Hans` mechanically. Prefer source Traditional names where available, then translate route, UI, and planning text into readable Traditional Chinese.

2. `ja`
   - Best stress test after `zh-Hant` because Japanese changes word order, route descriptions, and search keywords more than a Chinese variant.
   - Use this to verify the overlay schema is language-neutral and not accidentally tuned only for Chinese.

3. `ko`, then high-traffic Latin-script locales
   - `ko` catches CJK layout issues similar to Japanese.
   - Latin-script locales should follow only after the overlay workflow and quality gates are routine.

## Per-Locale Delivery Contract

Each data locale is publishable only when all of these are true:

- A complete `src/data/content/i18n/<locale>/data/` overlay directory exists with the same 12 files as `zh-Hans`.
- Published rows use `translationStatus: "translated"` and draft rows use `translationStatus: "draft"`.
- `npm run report:i18n:data` shows the intended release coverage. For a full data release, target 100%.
- `npm run validate:data` passes for schema, source IDs, duplicate IDs, empty overlay rows, and locale-specific quality rules.
- `npm run validate:i18n` passes after locale metadata or route behavior changes.
- `npm run build` proves localized list pages, detail pages, search index, sitemap, and feeds still generate.
- Release candidates run full `npm run qa`.

## Overlay Authoring Rules

- Translate only localized fields allowed by the overlay schemas in `src/data/heartopia.ts` and `scripts/validate-data.mjs`.
- Do not copy English fields into a non-English overlay just to hit coverage.
- Use `draft` for uncertain rows instead of publishing fallback body content into indexable locale pages.
- Keep IDs, route paths, image paths, and source URLs in English/source form unless the schema explicitly allows localized display fields.
- For source-derived names, prefer the authoritative source language where it matches the target locale.
- For route, use, notes, schedule, prep, and summary fields, write natural target-language planning copy rather than literal word swaps.

## Quality Gate Expansion

- Keep `zh-Hans` checks focused on high-confidence issues:
  - Traditional Chinese residue.
  - English placeholders such as `Unknown`, `TBA`, `pending`, `Placeholder`, and `fallback`.
  - Likely English residue outside approved product/source terms.
- Add per-locale quality checks as each locale is introduced. Do not apply zh-Hans-specific checks to `zh-Hant`, Japanese, Korean, or Latin-script locales.
- Prefer explicit allowlists for product names, source names, code values, and unavoidable game terms.

## Recommended Next Implementation

Start with `zh-Hant`:

1. Add `src/data/content/i18n/zh-Hant/data/` with the 12 overlay files.
2. Reuse Traditional source names and lore from `nameZh`/Wiki-backed rows where available.
3. Translate route-planning fields from the English source or from reviewed `zh-Hans` copy into Traditional Chinese.
4. Add `zh-Hant` coverage to `report:i18n:data` automatically through locale discovery.
5. Add a `zh-Hant` quality rule that blocks Simplified-only residue only where high confidence.
6. Run `npm run validate:data`, `npm run validate:i18n`, `npm run report:i18n:data`, `npm run build`, and then full `npm run qa` before release.
